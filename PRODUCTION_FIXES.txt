BRANCHING WORKFLOW
------------------
  prod   = production environment (DO NOT commit directly to prod)
  main   = staging environment (merge PRs here after review)
  fix/*  = one branch per fix, created FROM main

For each fix:
  1. git checkout main && git pull
  2. git checkout -b fix/<short-name>
  3. Implement the fix
  4. Commit with a clear message
  5. Push branch and open PR → merge into main
  6. prod stays untouched until you manually promote main → prod

One fix = one branch = one PR = one commit (or small logical commits in same PR).

Branch: fix/booking-overlap-race
Priority: CRITICAL
------------------------------------------------------------------------------

  Check-then-insert with no transaction. Unique index only blocks identical
  startTime, not overlapping slots. Two concurrent requests can double-book.

FILES:
  backend/src/models/Booking.js
  backend/src/controllers/bookingController.js  (createBooking)

  - OR retry on duplicate key with overlap re-check

VERIFY:
  Two simultaneous bookings for overlapping times on same barber → one fails.
